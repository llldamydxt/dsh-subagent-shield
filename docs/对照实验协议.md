# 子代理对照实验协议

配合 `dsh-subagent-shield` 使用。**这不是插件文档，是一份"照着做就不会白跑"的执行书。**

> 概念解释见 [说明书](说明书.md) 的「拿到可信结果的两条纪律」一节。
> 本文只讲**动作**：每条都给出可直接跑的命令。

---

## 0. 它解决什么 / 不解决什么

| | 靠什么 |
|---|---|
| 子代理去翻 **DSH 自己的记录**（父/兄弟会话、投影缓存、凭据） | ✅ 插件拦（有独立验证背书：7/7 拦 + 账本 + 零泄露） |
| 子代理去读 **别的臂的产物** | ✅ 插件拦（把目录挂进「臂间隔离」） |
| **口径漂移** | ❌ 插件管不了 —— 靠本协议第 1.1 条 |
| **答案键落在被试的搜索邻域** | ❌ 插件管不了 —— 靠本协议第 1.2 条 |
| 研究问题中途被换掉 | ❌ 靠任务书逐字稿 |

**记住排序**：泄露是第 4 名。前两名是**你自己的错，而且事后查不出来**。

## 1. 实验前（逐项做完再开跑）

### 1.1 钉死口径（15 分钟，省掉一次白跑）

- [ ] 写一份**逐字**的评分口径：算什么 / 怎么算 / 单位 / 小数位 / 输出格式
- [ ] 两臂发**同一份**口径（不要凭记忆口述）
- [ ] 判分用**同一个脚本**，跑完不要手改
- [ ] 自检：**把两臂输出交换名字，我还能用同一套规则分出优劣吗？** 答不上来就别开跑

### 1.2 扫答案键（5 分钟）

在被试能到达的每个目录里扫一遍像答案的东西：

```powershell
# 文件名可疑
Get-ChildItem "<臂目录>" -Recurse -File |
  Where-Object { $_.Name -match '真值|答案|标准|期望|truth|expected|answer|label' } |
  Select-Object FullName

# 内容可疑
Get-ChildItem "<臂目录>" -Recurse -File -Include *.md,*.json,*.txt,*.csv |
  Select-String -Pattern '答案|标准答案|正确结果|expected|ground.?truth' -List |
  Select-Object Path, Line
```

- [ ] 上一轮的产物**移出**被试能到的地方（不是改名）
- [ ] 任务书自己审一遍：有没有不小心把答案写进去
- [ ] 自检：**如果被试故意作弊，它最快能在哪个文件里找到答案？** 找得出就先挪走

### 1.3 固定自变量

- [ ] 一次只改**一个**东西。给了模板就别同时放开自由发挥。

### 1.4 目录结构

```
<实验根>\
  ├─ 臂A\        ← 臂A 的产物只能写这里
  ├─ 臂B\
  └─ 共享\       ← 两边都要读的输入放这里（不要放答案）
```

### 1.5 挂臂间隔离

**两条路，任选一条（也可以都不用，那就只靠纪律 + 第 3 节的审计）。**

#### 路 A：什么都不配 —— **谁写的谁拥有**（默认开，零配置）

子代理 `write`/`edit` 过的文件自动登记成它的；**另一个**子代理去读、或去 `glob`/`grep` 那个目录时被拦住。
**产物挤在同一个目录里也没关系** —— 这是它相对路 B 的主要优势。

- [ ] 确认开关是开的（设置 → 信息隔断 → 「谁写的谁拥有」，**默认开**）
- [ ] 派每个臂时 `description` **填个名字**（例如 `臂A` / `臂B`）—— 账本与拒绝文案里靠它认人
- [ ] 需要"一个子代理写、另一个子代理审"时，临时放行：`/shield 放行 <路径>`（收回用 `/shield 收回`）

> ⚠️ 它只管**走工具管线**的写入（`write` / `edit`）。子代理用 `pwsh` 写出来的文件**登记不到**。
> 而且**父会话写的文件不登记**（否则子代理连任务书都读不到）→ **答案键仍要自己放对地方**。

#### 路 B：显式挂目录（`protectedPaths`）—— 要更严的隔离时用

**设置 → 信息隔断 → 臂间隔离**，每个臂加一条：

| 字段 | 填什么 |
|---|---|
| 路径 | 该臂的产物目录，例如 `<实验根>\臂A` |
| 归属窗口 | 该臂那个**窗口**的 id —— 从设置页上面「按窗口」里复制。适合"一臂一窗口" |
| 归属标签 | **派该臂那个子代理时填的 description**，例如 `臂A`。适合"一个窗口开多个子代理当多臂" |
| （都留空） | 对所有人拦住 |

- [ ] 每个臂的产物目录都挂了（**挂上是机制，不挂就还是纪律**）
- [ ] **一臂一窗口** → 填归属窗口；**一个窗口开多个子代理** → 填归属标签（填派它时的 description）
- [ ] 这条路的布局前提：**每臂一个子目录**（目录级归属认不了"同一个目录里哪几个文件是我的"）

**归属标签是"让子代理跑对照实验"的关键** —— 因为它**在你派子代理之前就定下了身份**，
不存在"得先知道会话 id 才能配规则"的死结。

> 🔴 **为什么需要"归属标签"**（实测）：
> 同一个窗口下的两个子代理，`parentSession` **完全相同**：
> ```
> 臂A  parentSession = session-2db5727b-…（同一个）
> 臂B  parentSession = session-2db5727b-…（同一个）
> ```
> 所以**只靠窗口分不开它们** —— 归属窗口那套在"一窗口多子代理"下会一起放行/一起拦住。
> 加上**归属标签**（子代理的 description）之后，同一个窗口下的两个臂才分得开：
> ```
> 臂A：派它时 description 填「臂A」 →  规则 { path: "…\臂A", label: "臂A" }
> 臂B：派它时 description 填「臂B」 →  规则 { path: "…\臂B", label: "臂B" }
> ```
> 标签是**子串匹配**（`臂A` 能匹配 description `臂A（基线组）`），且大小写不敏感。
> 标签读不到时**判定更严**（不会误放行）。

> ⚠️ 用接口（`POST /dsh-subagent-shield/rules`）配规则时，**中文路径必须按 UTF-8 字节发**，
> 否则会被写成 `??????`、规则永远匹配不上：
> ```powershell
> $json = '{"protectedPaths":[{"path":"C:\\实验\\臂B","owner":"session-xxxx"}]}'
> Invoke-WebRequest -Uri 'http://127.0.0.1:3080/dsh-subagent-shield/rules' -Method POST `
>   -WebSession $sess -Body ([Text.Encoding]::UTF8.GetBytes($json)) `
>   -ContentType 'application/json; charset=utf-8'
> ```

### 1.6 记下护盾状态（**最容易漏、事后最要命**）

在任意窗口敲：

```
/shield status
```

把它输出的这几项**抄进实验记录**：

- [ ] `enabled`（总开关）
- [ ] `scope`（应该是 `subagents` —— 见第 5 节为什么不要用 `all`）
- [ ] `mode`
- [ ] 插件版本（`/status` 里的 `version`）

**漏了这一步，事后无法判断那次实验到底有没有被拦。**

## 3. 实验后（父侧审计 —— 这是唯一权威）

> 自述不可信，落盘记录是权威。**别问子代理"你有没有偷看"，去查记录。**

### 3.1 护盾账本：那次到底拦了什么

```powershell
$af = "$env:DSH_HOME\subagent-shield-audit.jsonl"
$rows = Get-Content $af | Select-Object -Last 20
$rows | ForEach-Object { $_ | ConvertFrom-Json } |
  Select-Object ts, tool, kind, target, window, callerIsSubagent | Format-Table -AutoSize
```

看三件事：

- [ ] **新增条数** = 你预期的拒绝次数？（对不上就要问为什么）
- [ ] `callerIsSubagent` 是否 `true`（身份判定生效）
- [ ] `kind` 分布：`sessions` / `projcache` / `credentials` / `shell` / **`custom`**（臂间隔离命中）

### 3.2 泄露检测：臂A 有没有看到臂B 的东西

原理：在臂B 的记录里放一个**只有臂B 知道**的字符串，然后去臂A 的记录里找它。

```powershell
# 找到两个臂的会话文件
Get-ChildItem "$env:DSH_HOME\sessions" -Recurse -File -Filter 'session.v4.jsonl.zstd' |
  Sort-Object LastWriteTime -Descending | Select-Object -First 5 FullName, LastWriteTime

# 在臂A 的记录里找臂B 独有的字符串（期望 0 命中）
node decode-session.mjs "<臂A 的 session.v4.jsonl.zstd>" "<臂B 独有的字符串>"
```

- [ ] 命中 **0** 才算没泄露
- [ ] 反向对照：同一条命令换成臂A 自己的字符串，应当**有命中**（证明检索方式有效）

> 🔴 **标记必须"只存在于对方那儿、且从没出现在你给它的指令里"。**
> 实测踩过：我在给两臂的指令里写了"不要碰 `臂B`/`臂A`" —— 于是**对方的臂名必然出现在各自记录里**，
> 拿臂名当标记会得到**假阳性**。
> 正确做法：在对方目录里埋一个**随机串**（例如 `ARM-B-SECRET-a1b2c3d4`），
> 只在对方那份任务书/产物里出现，你的指令里一个字都不提。

> ⚠️ 会话记录是**多帧 zstd**（一次工具调用一帧），普通解压只出第一帧 ——
> 必须用 `tools/decode-session.mjs`（**本仓库自带**）：
> ```powershell
> node tools/decode-session.mjs "<会话记录.v4.jsonl.zstd>" "<要检索的字符串>"
> ```

### 3.3 产物审计（护盾不拦的那条通道，只能靠这里查）

如果两臂是**同一个窗口**的两个子代理，或者任何一个产物目录**没挂**进臂间隔离，
护盾不会拦 —— 这时只能靠审计：

```powershell
# 臂A 的记录里有没有出现"臂B 目录里独有的东西"
node decode-session.mjs "<臂A 的 session.v4.jsonl.zstd>" "<只存在于臂B 目录的随机串>"
node decode-session.mjs "<臂A 的 session.v4.jsonl.zstd>" "臂B"      # 目录名；注意上面那个假阳性警告
```

- [ ] 0 命中
- [ ] 判"这是哪个臂"用会话头（`origin` / `parentSession`），别靠猜文件时间：
  ```powershell
  node tools/dump-header.mjs "<某个 session.v4.jsonl.zstd>"
  ```

### 3.4 判分

- [ ] 用 1.1 钉死的那份脚本，**不手改**
- [ ] 有条件就做一次**盲评**（交换名字）

## 4. 入库格式（每条实验记录必写）

```
实验：<一句话研究问题>
护盾：enabled=… scope=… mode=… version=…
自变量：<这一次唯一改动的东西>
口径逐字稿：<路径>  sha256=<…>
各臂任务书：<路径>  sha256=<…>
臂间隔离：<路径 → 归属窗口> 列表
审计：账本新增 <N> 条（kind 分布 …）；泄露检测 0 命中；产物审计 0 命中
结论：<…>
停手线是否触发：否 / 是（哪一臂，为什么）
```

## 5. 已知做不到的（边界）

- **命令族是文本启发式**：命令行里**拼接/变量/base64** 绕过路径文本，就拦不住。
  路径族（`read`/`write`/`glob`/`grep` 的参数）是**精确**的。
- **`scope` 请固定 `subagents`**：`scope=all` 会把**父会话的审计通道**也挡住，
  而第 3 节的审计是判谁污染的唯一权威手段 —— 那等于自断眼睛。
- **护盾不是 OS 边界**：同机其它进程、以及不经过工具的访问，它管不了。
- **产物默认不拦**：只有挂进「臂间隔离」的目录才拦。
- **它管不了口径与答案键**：这两条永远靠第 1.1 / 1.2 条的人工动作。

## 附：这套协议的来源

- 第 3 节的审计动作、`decode-session.mjs`（多帧解码）、以及"父侧对照"的写法，
  来自本项目的《护盾独立验证报告》——
  那份报告里用**真子代理 A/B/C** 跑过两轮对撞，并把逐字证据留了档。
- 「臂间隔离」这个功能本身就是那份报告逼出来的：实测发现护盾**完全不管实验产物**，
  子代理 C 直接读到了兄弟臂写下的文件。
- 两个审计工具随本仓库分发在 `tools/`：`decode-session.mjs`（多帧 zstd 解码 + 关键词检索）、
  `dump-header.mjs`（打印会话头的 origin / parentSession / delegationDepth，用来判断"这是哪个臂"）。
