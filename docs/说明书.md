# 子代理信息隔断 · 使用说明书

> 适用版本：`dsh-subagent-shield` 0.1.0（v2）· 本机 DSH `0.2.0-rc.2` · DSH_HOME = `%DSH_HOME%`
> 本机状态：**已安装并已在真机上验收通过**（见第 7 节实测记录）。

---

## 1. 它解决什么问题

DSH 把每个会话的完整记录按工作目录分组落盘，父会话与全部子代理**并列在同一个目录**下，
只做 zstd 压缩、不加密：

```
%DSH_HOME%\sessions\<cwd编码>\<session id>\session.v4.jsonl.zstd
```

于是**任何一个子代理都能读出父会话和兄弟子代理的全部记录**（含每一次工具调用与输出），
此外还有明文的投影缓存 `storages\session_projcache\` 和凭据文件 `.credentials.yaml`。

本插件在工具调用这一层装一道门：**子代理**去碰这些位置时直接拒绝，并把每次拒绝记进账本。

## 2. 它拦什么、按什么判定

| 受保护位置 | 为什么 |
|---|---|
| `%DSH_HOME%\sessions\**` | 父会话 + 全部兄弟子代理的完整落盘记录（泄露主通道） |
| `%DSH_HOME%\storages\session_projcache\**` | 明文投影缓存（含进行中的提示词、todos、草稿） |
| `%DSH_HOME%\.credentials.yaml` | 明文凭据（含 API key 与 GUI 的 cookie 签名密钥） |
| 本插件自己的账本 / 状态文件 | 不然子代理可以读它、删它 |

判定分两族，**可信度不同**：

| 族 | 覆盖的工具 | 判定方式 | 可信度 |
|---|---|---|---|
| 路径族 | `read` `read_image` `write` `edit` `str_replace_editor` `glob` `grep` | 取那个决定访问位置的参数，归一化（大小写 / 正反斜杠 / `\\?\` 前缀 / `.` 与 `..` / 首尾引号）后与受保护根做前缀比较 | **精确** |
| 命令族 | `pwsh` `bash` `run_code` `cordis_define` | 按命令行文本启发式匹配 | **启发式，可被绕过** |

命中后返回：

```
【已隔断】不得访问<受保护位置>。
路径：<原始路径>
这是策略决定，不是临时故障，请勿重试或用其它方式绕过。
```

最后一句是刻意加的 —— 没有它，被拒的模型会反复重试同一个调用。

## 3. 默认行为

| 配置 | 默认值 | 含义 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `scope` | `subagents` | **只挡子代理，父会话不受限** |
| `mode` | `all` | 所有窗口的子代理都隔断 |
| `protectSessions` | `true` | 隔断会话落盘目录 |
| `protectProjcache` | `true` | 隔断投影缓存 |
| `protectCredentials` | `true` | 隔断凭据文件 |
| `guardShellText` | `true` | 对命令族做文本启发式拦截 |
| `auditEnabled` | `true` | 每次拒绝写一行账本 |
| `auditFile` | 空 | 留空 = `<DSH_HOME>\subagent-shield-audit.jsonl` |

**父会话默认不受限**，因为你还要读会话记录做审计；想连父会话一起挡，把 `scope` 改成 `all`
（代价：你自己的 `read`/`pwsh` 读会话记录也会被拒，那时事后审计只能靠账本，或先 `/shield off`）。

## 4. 日常怎么用

### 4.1 本窗口开关（最常用）

在输入框直接敲：

| 命令 | 作用 |
|---|---|
| `/shield on` | 本窗口隔断（`mode=window` 时用它开启） |
| `/shield off` | 本窗口豁免（`mode=all` 时用它放行，比如你自己要审计） |
| `/shield clear` | 清掉本窗口的覆盖，回到默认 |
| `/shield status` | 看本窗口当前状态、范围、总开关、账本路径 |

按窗口的设置会写进 `<DSH_HOME>\subagent-shield-state.json`，**重启后仍在**。

### 4.2 设置页：独立分区「信息隔断」

设置左侧导航里会多一项 **信息隔断**（和「皮肤市场」同一层的独立分区，不再塞在插件卡里）。

| 分区里的区块 | 作用 |
|---|---|
| 总开关 | `enabled` 启用隔断；命令行文本启发式（可被拼接绕过，属尽力而为） |
| 隔断范围 / 模式 | `scope`（subagents 只挡子代理 / all 连父会话一起挡）、`mode`（all 所有窗口 / window 只挡被 `/shield on` 点名的窗口） |
| **保护对象与默认策略** | `默认保护全部`，或 `默认不保护（只保护下面点名的）` |
| **按工作区（自动发现）** | 列出 `%DSH_HOME%\sessions` 下每个工作区（目录名反解可读路径 + 窗口数 + 最近时间），逐个勾选 |
| **按窗口（最近 60 个）** | 列出每个会话窗口（id + 所属工作区 + 时间），逐个勾选 |
| 逐项保护 | 会话落盘记录 / 投影缓存 / 宿主凭据文件 |
| 事后账本 | 开关 + 账本路径 |
| 统计与最近拒绝 | 拒绝总数、涉及窗口数、最近 8 条明细 |
| 状态小窗 | 开/关页面上的浮动小窗 |

**优先级：单个窗口 > 单个工作区 > 默认策略。**

例：默认保护全部 → 把某个工作区设为豁免 → 再把该工作区里某个窗口设回保护 ⇒ **那个窗口仍然受保护**；同一工作区里的其它窗口则放行。

规则存在 `<DSH_HOME>\subagent-shield-rules.json`；页面通过 `/dsh-subagent-shield/rules` 读写（在「设置 → 信息隔断」里改动即时生效，无需重启）。

改完**立即生效**（全局开关写回 profile 的 Cordis patch，重启后仍在；目标规则写进规则文件）。

**② 浮动状态小窗** —— 页面上一个可拖动、可收起、可关掉的小浮窗：

| 操作 | 怎么做 |
|---|---|
| 移动 | 按住**标题栏**拖 |
| 收起 | 点标题栏的 **−**（只留标题栏） |
| 关闭 | 点标题栏的 **✕**（缩成角落一个 🛡 圆点，点它恢复） |
| 看数据 | 每 3 秒自动拉一次；也可点**刷新** |

小窗显示：总开关/范围/模式 · 已拒绝次数与涉及窗口数 · **最近 5 条拒绝**（时间 工具 命中类型 窗口）。
**位置、收起、开关状态都记在浏览器 localStorage，刷新后保持。**

想彻底不要它：卡片里点「关闭状态小窗」，然后刷新页面。

### 4.3 四种典型用法

| 你想干什么 | 怎么设 |
|---|---|
| 跑对照实验，不让臂互相偷看（大多数情况） | **什么都不用改**，默认就是 |
| 只在某个窗口隔断，别的窗口不管 | 设置里把 `mode` 改成 `window`，再到那个窗口敲 `/shield on` |
| 临时要读会话记录做审计 | 在那个窗口敲 `/shield off`（或设置里关 `enabled`） |
| 更彻底：连父会话一起挡 | 设置里把 `scope` 改成 `all` |

### 4.4 查谁被拦了（事后检测）

账本：`<DSH_HOME>\subagent-shield-audit.jsonl`，每行一个 JSON：

```json
{"ts":"…","action":"deny","kind":"sessions","tool":"glob",
 "target":"…\\sessions","window":"session-2db5727b-…","scope":"subagents",
 "callerIsSubagent":true,"caller":"bd1b80b9-…","mode":"all"}
```

| 字段 | 含义 |
|---|---|
| `kind` | 命中哪一类：`sessions` / `projcache` / `credentials` / `shell` / `audit` / `state` |
| `tool` | 被拒的工具名 |
| `target` | 具体路径（命令族是命令文本片段） |
| `window` | 哪个窗口（顶层会话 id） |
| `caller` | 发起调用的会话 id（子代理） |
| `scope` / `mode` | 当时生效的设置，便于回溯 |

看最近 10 条：

```powershell
Get-Content "$env:DSH_HOME\subagent-shield-audit.jsonl" -Tail 10
```

## 6. 安装 / 卸载 / 排查

### 6.1 安装（重装、升级、换机器）

双击 `实验台\安装隔离插件\安装.cmd`。它会：备份配置 → 装插件 → **自验**（包解析 + 配置合成）
→ 验不过就**自动回滚**并退出。也可以加 `-DryRun` 只看不干。

### 6.2 重启才生效（有个坑）

```powershell
& "C:\Users\you\Desktop\工作区\有关世界上最棒最可爱的蓝色使用者\超级蓝色使用者启动器\launch-dsh.ps1" -Restart
```

**必须带 `-Restart`**：直接双击日常启动器会看到端口已被占用、判定"复用现有实例"，插件不会加载。

### 6.3 卸载

```powershell
$live = "$env:DSH_HOME"   # 本机 = %DSH_HOME%
Copy-Item "$live\profiles\web\cordis.patch.yml.bak-shield-20261010-164555" `
          "$live\profiles\web\cordis.patch.yml" -Force
Remove-Item "$live\profiles\web\node_modules\dsh-subagent-shield" -Recurse -Force
```

（备份文件名带时间戳，装的时候会打印出来；实在找不着就用下面的修复工具。）

### 6.4 排查表

| 症状 | 原因 / 处理 |
|---|---|
| 重启后 `/shield` 没反应、账本也不生成 | 插件没加载。先确认启动时带了 `-Restart`；再跑第 5 节自检 1、2 步 |
| **装了之后 DSH 起不来** | 双击 `实验台\修复\一键修复使用者.cmd`，它会读启动日志、认出坏条目、注释掉并重启 |
| 账本文件不存在 | 说明还没发生过拒绝；或设置里 `auditEnabled=false` |
| 子代理被误伤（正常任务被拒） | 在那个窗口敲 `/shield off`；或设置里关掉对应的 `protect*` 项 |
| 想让父会话也能读、但子代理不行 | 这就是默认设置（`scope=subagents`），无需改动 |
| 父会话自己也被拒了 | 说明 `scope` 被改成了 `all`。改回 `subagents`，或在窗口里 `/shield off` |

## 8. 它做不到什么（务必知道）

1. **这是工具层策略围栏，不是内核边界。** DSH 的 `fs` 接口只声明
   `fs/write-intent` / `fs/edit-intent` / `fs/observed`，**没有 `fs/read` 钩子** ——
   插件无法在文件系统层拦读。要真在那一层拦，只能整体替换 `ctx.fs` provider。
2. **命令族可被绕过**：拼接、变量间接引用、`[char]` 构造、base64、`cmd /c` 套壳……
   启发式拦的是"手滑和惯性触碰"，不是"恶意对抗"。
3. **不等价于硬隔离。** 真正要硬保证，仍是：**不同 OS 账户 / 容器 / 另一台机器，各配独立 DSH_HOME**。
4. 它**不加密**任何东西，也**不改**会话落盘布局 —— 那些没有插件钩子可用。
5. 按窗口的覆盖以"父会话 id"为键；嵌套子代理（子代理再开子代理）归属其直接父会话，
   深度 >1 的场景未单独验证。

## 臂间隔离（自定义拦住目录）

跑对照实验时，各个臂往往会往工作区里写产物（结果、笔记、中间文件）。
护盾**默认不管**这些文件 —— 两个子代理互相读对方的产物是允许的。

要隔开，就在 **设置 → 信息隔断 → 臂间隔离** 里加一条：

| 字段 | 填什么 |
|---|---|
| 路径 | 要拦住的目录，例如 `C:\lab\armB` |
| 归属窗口 | 谁的专属目录 —— 从设置页上面「按窗口」里复制那一串 id；**留空 = 对所有人拦住** |

效果：只有归属窗口（以及它的子代理）能读写该目录；其它窗口与其子代理，
不论 `read` / `glob` / `grep` / `write` 这类工具，还是命令行里**字面**出现该路径，都会被拦。

两条注意：

- **归属 id 的前缀可有可无**：`session-xxxx` 与 `xxxx` 都认（同一会话在 DSH 不同字段下格式不一致）。
- 命令行那条仍是**文本启发式**：拼接 / 变量 / base64 可绕 —— 与命令族其它模式的边界一样。
