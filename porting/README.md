# 移植指南：把它搬到别的 Agent 宿主

> 这个插件是**给 DSH 写的**，而且只在 **DSH + Windows** 上验证过。
> 但真正跟 DSH 绑死的只有**一层薄薄的适配层**；判定语义、配置模型、审计与验证方法都是通用的。
> 这个文件夹写清楚：**换宿主需要什么**。

## 0. 一句话

**要重写的是"怎么挂上去、怎么认出调用者"；能整段搬走的是"怎么判、怎么记、怎么验"。**

如果你只做一件事：把 [spec.md](spec.md) 的判定语义按你宿主的形状重新实现一遍适配层，
再用 [verify.md](verify.md) 的对撞实验验一次 —— 别信"看起来能拦"。

## 1. 哪些能搬，哪些不能

| | 内容 | 说明 |
|---|---|---|
| ✅ **整段搬** | 判定语义（`spec.md`） | 纯函数：解析路径 → 分类 → 按规则决定拦不拦 → 归属豁免 |
| ✅ **整段搬** | 配置模型 | `defaultPolicy` + `workspaces` + `windows` + `protectedPaths[{path,owner,label}]` |
| ✅ **整段搬** | 审计账本格式 | 一条 JSON Lines：`ts/action/kind/tool/target/window/scope/callerIsSubagent/caller/mode` |
| ✅ **整段搬** | 拒绝文案模板 | 见 `spec.md` §5（要写明"这是策略决定，请勿绕过"） |
| ✅ **整段搬** | 验证方法 | `verify.md`：控制组 + 真子代理对撞 + 零泄露检索 |
| ⚠️ **要改** | 钩子挂载 | 换成宿主的工具前置钩子（必须能**否决**并给出理由） |
| ⚠️ **要改** | 调用者身份 | 换成宿主能提供的身份字段（见 §2 的能力契约） |
| ⚠️ **要改** | 敏感路径清单 | DSH 的 `sessions`/`storages`/凭据文件换成你宿主的对应物 |
| ❌ **别搬** | `lib/client.js` | 是 DSH 设置页的槽位实现，换个宿主等于重写 UI |
| ❌ **别搬** | `cordis.patch.yml` / `package.json` 的 `dsh.client` | DSH/Cordis 的插件机制 |
| ❌ **别搬** | Windows 路径假设 | 盘符、反斜杠、统一小写 —— POSIX 上会出边界问题，见 §5 |

## 2. 宿主能力契约（逐项确认，缺哪项就得降级）

移植前把这张表填完。**每一项都要用真实运行验证，不能看文档猜。**

| # | 能力 | 必需? | 缺了会怎样 |
|---|---|---|---|
| **C1** | **工具调用前置钩子**，能拿到工具名 + 参数 + 调用者，并且能**否决**这次调用（带自定义理由） | 🔴 必需 | 做不了事前隔断，只能做事后审计（价值差一个数量级） |
| **C2** | **调用者是不是子代理** | 🔴 必需 | 分不清父/子，`scope` 无从谈起 |
| **C3** | **调用者身份**：父会话 id（"窗口"）／子代理自己的会话 id／派发时的标签（description） | 🔴 必需 | 臂间隔离分不开（DSH 里就是靠标签才分开同窗口的两个子代理） |
| **C4** | **敏感存储的稳定位置**：会话记录、缓存、凭据 | 🔴 必需 | 不知道该保护什么 |
| **C5** | **可写的规则/状态文件**位置 | 🟠 需要 | 配置无法持久化 |
| **C6** | **子会话记录可读**（含派发时的标签） | 🟠 推荐 | 拿不到标签时有兜底路径；没有就只能靠会话 id 归属 |
| **C7** | 设置界面槽位 | 🟢 可选 | 退化到改配置文件 |
| **C8** | 宿主自身的鉴权（给 HTTP 接口用） | 🟢 可选 | 接口必须自己加鉴权，**不能裸奔** |

> ⚠️ **C3 是最容易低估的一项。** DSH 的实测教训：同一个父会话下的两个子代理，
> `parentSession` **完全相同** —— 只按"窗口"归属会把它们一起放行/一起拦住。
> 必须有**逐个子代理可区分**的身份（DSH 里是派发时填的 `description`，落成一条 descriptor 记录）。
> 如果你的宿主给不出这个，臂间隔离就只能靠**任务书纪律 + 父侧审计**。

## 3. 适配层要实现的接口

把 DSH 的实现拆出来，适配层只需要这几个函数（语义见 [adapter.md](adapter.md)）：

```js
// ① 身份：这次调用是谁发起的
host.identity(exec) -> {
  isSubagent: boolean,
  window:     string | null,   // 父会话（"窗口"）id
  callerId:   string | null,   // 调用者自己的会话 id
  label:      string | null,   // 派发时给的标签（子代理才有）
}

// ② 目标：这次调用碰到了什么路径（可能多个：glob 的 pattern 也是路径）
host.targets(exec) -> string[]        // 原始路径字符串

// ③ 敏感清单：宿主自己的记录/缓存/凭据在哪
host.sensitiveRoots(home) -> [{ path, kind, label }]
                                      // kind: 'sessions' | 'projcache' | 'credentials' | 'state'

// ④ 工作区/窗口元数据：给设置界面列清单、给"按工作区/窗口"策略用
host.listWorkspaces() -> [{ key, label, sessions, latest }]
host.listWindows()    -> [{ id, label, workspace, latest }]

// ⑤ 否决
host.deny(reason) -> <宿主要求的返回值>
```

**其余部分（`spec.md` 里的判定、规则模型、账本、拒绝文案）不依赖宿主，照搬即可。**

## 4. 移植步骤

1. **填完 §2 的能力契约表**（真跑一遍，别猜）。任何一项 🔴 拿不到，先决定怎么降级，并**在 README 里写明降级后的边界**。
2. **照 [spec.md](spec.md) 实现判定核心**（建议保持纯函数 + 不碰 IO，便于单测）。
3. **实现 §3 的适配层**，把宿主身份/路径/敏感清单接进去。
4. **照 [verify.md](verify.md) 跑四项对撞**，全过才算移植成功。
5. 把 §2 表里"没做到的那几项"写进你自己的 README —— **这一条比功能更重要**：
   使用者必须知道边界在哪，否则会把"防手滑的围栏"当成"安全边界"用。

## 5. 常见坑（都是我在 DSH 上踩过的）

| 坑 | 后果 | 怎么办 |
|---|---|---|
| 只按"父会话"归属 | 同窗口的多个子代理分不开，一起放行/一起拦 | 引入逐子代理身份（C3） |
| 以为文本启发式是安全边界 | 命令行里拼接/变量/base64 就绕过去了 | 明说它是启发式；路径族要**精确**匹配 |
| 路径匹配不要求分隔符结尾 | `…\臂A` 误吃 `…\臂A2` | 比较 `t === p \|\| t.startsWith(p + sep)` |
| 不处理 `..` 与大小写 | 绕过或误伤 | 归一化后再比（大小写策略随宿主） |
| 空输入返回了分隔符 | `x \|\| 默认值` 走错分支（DSH 上真的让账本失去保护） | 空串就返回空串 |
| 会话 id 前缀不一致 | 归属者被自己的目录拦住（DSH 上真的踩过） | 比之前归一（剥可选前缀、忽略大小写） |
| 拒绝理由写得含糊 | 使用者排查被带偏（DSH 上真的踩过：纯标签规则却说"未指定归属窗口"） | 文案按**实际配的那一种归属**说 |
| 忘了记"调用者是不是子代理" | 事后无法判断那条记录怎么来的 | 账本必带 `callerIsSubagent` + `caller` |
| **只跑作者自己的测试** | 自述"能拦"没有外部证据 | 必须用**真子代理**跑 `verify.md` |

## 6. 明确不承诺的事

- **不是 OS 边界**：同机其它进程、以及不经过工具管线的访问，拦不住。
- **不是沙箱**：不隔离进程、不限制网络。
- **跨平台未验证**：DSH + Windows 之外的组合属于"需要你按 [verify.md](verify.md) 自己验"。
- **宿主升级可能弄坏它**：身份字段与记录格式都不是稳定 API。DSH 版做了两层兜底
  （服务取不到就读会话记录），但兜底同样依赖当前实现。
